## User Scenarios & Testing *(mandatory)*

### User Story 1 - Access LinkedIn Import View from Home (Priority: P1)

As a user viewing the Home page, I want to click a prominent floating action button at the top-right corner labeled "Import LinkedIn CSV" so that I can open a dedicated Import View to upload my LinkedIn export data.

**Why this priority**: Core entry point that enables users to initiate the import workflow without disrupting current navigation.

**Independent Test**: Can be tested by navigating to Home, verifying the floating button exists in the top-right corner, clicking it, and confirming the view switches to the 2-column Import View with a working Back button.

**Acceptance Scenarios**:

1. **Given** the user is on the Home View, **When** they look at the top-right corner, **Then** they see a floating button with text "Import LinkedIn CSV".
2. **Given** the user clicks "Import LinkedIn CSV", **When** the action completes, **Then** the view transitions to the Import View displaying a "Back button" and a 2-column layout (instructions on the left, file drop/picker on the right).
3. **Given** the user is on the Import View, **When** they click the "Back button", **Then** the application returns to the Home View.

---

### User Story 2 - Upload ZIP File & View Real-Time Progress (Priority: P2)

As a user on the Import View, I want to select or drag-and-drop a LinkedIn data export `.zip` file so that the application extracts and processes my professional data while providing live progress feedback and prompting me on pre-existing data handling.

**Why this priority**: Essential interaction for ingesting data with dynamic visual feedback so the user knows the processing state and controls their data options.

**Independent Test**: Can be tested by dropping a valid `.zip` file onto the dropzone or selecting it via file picker, verifying the pre-existing data prompt appears if existing data is present, verifying the progress bar animates with step-by-step text updates, and confirming completion.

**Acceptance Scenarios**:

1. **Given** the user is on the Import View and selects a `.zip` file, **When** pre-existing resume data exists, **Then** a prompt asks the user to choose between replacing or keeping/merging their pre-existing data before processing begins.
2. **Given** import processing is active, **When** files are extracted and parsed, **Then** a visible progress bar updates dynamically with feedback messages for each file being processed (e.g. "Extracting Profile.csv...", "Parsing Work Experience...", "Updating Resume...").
3. **Given** an invalid or corrupted non-ZIP file is provided, **When** processing starts, **Then** an error message is displayed allowing the user to select another file.

---

### User Story 3 - Complete Import & Populate JSON Resume (Priority: P3)

As a user whose LinkedIn ZIP has finished processing, I want to see a success message and click a button to return to the Home View where my updated resume data is reflected.

**Why this priority**: Finalizes the import flow and confirms data persistence.

**Independent Test**: Can be tested by completing a ZIP import, verifying the success state UI, clicking the return button, and verifying the Home view displays the imported profile, work, education, skills, and languages.

**Acceptance Scenarios**:

1. **Given** the ZIP file parsing completes successfully, **When** all CSV data is mapped to JSON Resume schema, **Then** a success message and a "Return to Home" button appear on screen.
2. **Given** the user clicks "Return to Home" after a successful import, **When** Home View loads, **Then** the global resume store reflects the newly imported data across all sections.

---

### Edge Cases

- What happens when an optional CSV file (such as `Certifications.csv` or `Projects.csv`) is missing from the ZIP archive? The importer MUST skip missing optional files gracefully without aborting the entire import process. At the end of the process must show which optional files were skipped.
- What happens if `Email Addresses.csv` contains multiple emails? The importer MUST select the primary or confirmed email address.
- What happens if `Finished On` in `Positions.csv` is empty? The importer MUST set `endDate` to `"Currently"`.
- What happens if pre-existing resume data is present during import? The importer MUST prompt the user to choose between "Replace" (overwrite existing data) or "Keep/Merge" (append to existing data) before writing updates. This must happens whe the function catches pre-existing data.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Home page MUST render a floating button in the top-right corner with the text "Import LinkedIn CSV".
- **FR-002**: Clicking the floating button MUST switch the current view from Home View to Import View.
- **FR-003**: Import View MUST contain a 2-column layout: the left column displaying step-by-step instructions on how to download a LinkedIn data export ZIP, and the right column containing a drag-and-drop zone / file selector.
- **FR-004**: Import View MUST contain a top "Back button" that returns the user to Home View.
- **FR-005**: Main process backend MUST read and unpack uploaded `.zip` files using the `adm-zip` library.
- **FR-006**: Backend importer MUST extract and parse the following CSV files and map them to `src/main/shared/schema/resumeSchema.ts`:
  - `Profile.csv` (`First Name` + `Last Name` $\rightarrow$ `basics.name`, `Headline` $\rightarrow$ `basics.label`, `Summary` $\rightarrow$ `basics.summary`, `Address`/`Zip Code`/`Geo Location` $\rightarrow$ `basics.location`, `Websites` $\rightarrow$ `basics.url` / `basics.profiles`)
  - `Email Addresses.csv` (Confirmed/Primary `Email Address` $\rightarrow$ `basics.email`)
  - `PhoneNumbers.csv` (`Number` + `Extension` $\rightarrow$ `basics.phone`)
  - `Positions.csv` (`Company Name` $\rightarrow$ `work[].name`, `Title` $\rightarrow$ `work[].position`, `Started On` $\rightarrow$ `work[].startDate`, `Finished On` $\rightarrow$ `work[].endDate` [default `"Currently"`], `Description` $\rightarrow$ `summary`/`highlights`)
  - `Education.csv` (`School Name` $\rightarrow$ `education[].institution`, `Degree Name`/`Activities` $\rightarrow$ `education[].area`/`studyType`, `Start Date` $\rightarrow$ `education[].startDate`, `End Date` $\rightarrow$ `education[].endDate` [default `"Currently"`])
  - `Skills.csv` (`Name` $\rightarrow$ `skills[].name`, `[Name]` $\rightarrow$ `skills[].keywords`)
  - `Languages.csv` (`Name` $\rightarrow$ `languages[].language`, `Proficiency` $\rightarrow$ `languages[].fluency`)
  - `Projects.csv` (`Title` $\rightarrow$ `projects[].title`, `Description` $\rightarrow$ `projects[].description`, `Url` $\rightarrow$ `projects[].url`, `Started On` $\rightarrow$ `projects[].startDate`, `Finished On` $\rightarrow$ `projects[].endDate`)
  - `Certifications.csv` (if present: `Name` $\rightarrow$ `certificates[].name`, `Authority` $\rightarrow$ `certificates[].issuer`, `Started On` $\rightarrow$ `certificates[].date`, `Url` $\rightarrow$ `certificates[].url`)
- **FR-007**: During import, the frontend MUST display a progress bar with dynamic message updates reflecting the current step of import.
- **FR-008**: Upon successful import completion, the system MUST display a clear success state and update the JSON Resume data store.
- **FR-009**: When pre-existing resume data exists, the application MUST prompt the user to choose whether to replace pre-existing resume data or keep/merge it before performing the import operation.

### Key Entities

- **`LinkedInImportPackage`**: Represents the uploaded ZIP file payload and its internal CSV contents.
- **`ImportProgressState`**: Represents the current stage of import (`idle` | `extracting` | `parsing` | `saving` | `complete` | `error`), progress percentage (0-100), and dynamic feedback string.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can navigate from Home View to Import View in under 1 click / instant transition.
- **SC-002**: ZIP extraction and CSV data parsing completes in under 3 seconds for standard LinkedIn export archives.
- **SC-003**: 100% of extracted valid CSV fields correctly map to JSON Resume schema fields without data corruption.
- **SC-004**: Users receive real-time progress feedback with status updates changing at least once per processed CSV section.

## Assumptions

- The uploaded ZIP file follows the official LinkedIn Data Export format.
- If optional CSV files (e.g. `Certifications.csv`) are absent in the archive, the importer proceeds without throwing errors.
- Exported dates are string representations (e.g., "Aug 2025") which will be preserved as strings in the resume schema.
